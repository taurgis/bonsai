# SessionStart Hook Event Reference (Claude Code)

`SessionStart` fires when Claude Code starts a new session or resumes an existing one.

Performance note: SessionStart runs on every session, so keep hooks fast.

## Matcher values

SessionStart supports matchers based on how the session was initiated:

| Matcher   | When it fires                                                                      |
| --------- | ----------------------------------------------------------------------------------- |
| `startup` | New session                                                                          |
| `resume`  | `--resume`, `--continue`, or `/resume`                                               |
| `clear`   | `/clear`                                                                             |
| `compact` | Auto or manual compaction                                                            |
| `fork`    | New session forked from existing: `--fork-session`, `/fork` background copy, `/branch` |

Example configuration:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/load-context.sh"
          }
        ]
      }
    ]
  }
}
```

## JSON input schema

In addition to common input fields (`session_id`, `transcript_path`, `cwd`, `hook_event_name`), SessionStart receives `source` (`"startup"`/`"resume"`/`"clear"`/`"compact"`/`"fork"`), plus optional `model`, `agent_type`, and `session_title`.

## JSON output: adding context

Any stdout text is added as context, or use structured JSON:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "Current branch: main. Recent issues: #123 (bug), #124 (feature)."
  }
}
```

The context appears in Claude's context window before the first prompt as a system reminder.

## Configuration locations

Hooks are defined in JSON settings files at three levels:

| Location                     | Scope             | Shareable | Notes                      |
| ----------------------------- | ------------------ | --------- | --------------------------- |
| `~/.claude/settings.json`     | All projects       | No        | Local to your machine      |
| `.claude/settings.json`       | Single project     | Yes       | Can be committed to the repo |
| `.claude/settings.local.json` | Single project     | No        | Gitignored; local overrides |
| Managed policy settings       | Organization-wide  | Yes       | Admin-controlled            |

## Exit codes & error handling

| Exit Code | Behavior                                                                        |
| --------- | -------------------------------------------------------------------------------- |
| `0`       | Success. Stdout parsed for JSON or shown as context.                             |
| `2`       | Error. Stderr shown in transcript as `<hook name> hook error`. Session proceeds. |
| Other     | Non-blocking error. Session proceeds.                                            |

Important: SessionStart cannot block session start — exit code 2 shows an error but doesn't prevent startup.

## Environment variables

- `$CLAUDE_PROJECT_DIR`: Project root
- `$CLAUDE_PLUGIN_ROOT` / `$CLAUDE_PLUGIN_DATA`: plugin installation/data directories (plugin hooks)
- `$CLAUDE_CODE_REMOTE`: `"true"` in web environments
- Parent shell environment is inherited

## Key limitations for SessionStart

1. No matchers for event occurrence beyond `source` (startup/resume/clear/compact/fork).
2. Cannot block session start.
3. Only `command`/`mcp_tool` handlers supported.
4. Default timeout 600 seconds.
5. No `permissionDecision` — that field is `PreToolUse`-specific.

# SessionStart Hook Event Reference (Claude Code)

`SessionStart` fires when Claude Code starts a new session or resumes an existing one. It's useful
for loading development context (issues, recent changes, environment state) or setting up
environment variables. For static context, use CLAUDE.md instead.

Performance note: SessionStart runs on every session, so keep hooks fast. Only `type: "command"`
and `type: "mcp_tool"` hooks are supported — no `prompt` or `agent` hooks.
